# 1C Configuration Inspector (`onec-inspector`)

Универсальный плагин, AI-скилл (`SKILL.md`), CLI-инструмент и MCP-сервер для чтения, анализа и аудита любых конфигураций и файловых баз данных **1С:Предприятие 8** (`.dt`, `.1CD`, `.cf`, `.cfe`, `.epf`, `.ert`, `.efd` или распакованный каталог) на базе библиотеки [`onec_dtools`](https://github.com/infactum/onec_dtools).

Позволяет AI-агентам (Antigravity, Claude Code, Cursor и др.) и разработчикам мгновенно исследовать метаданные, код модулей BSL, схемы СКД, управляемые/обычные формы, роли, пользователей и данные в физических таблицах `.1CD` / `.dt` — **без написания одноразовых скриптов-парсеров и без ручного запуска Конфигуратора**.

---

## ✨ Основные возможности

1. **Дерево метаданных и подсистемы (`summary`, `subsystems`, `object`)**
   - Поддержка всех 35+ классов метаданных 1С:Предприятие 8.
   - Полная расшифровка реквизитов и их типов (`Pattern` → `Строка(N)`, `Число(L,D)`, `Дата`, `Булево`, составные типы и ссылки на справочники/документы/перечисления).
   - Табличные части, измерения/ресурсы регистров, движения документов (`RegisterRecords`), значения перечислений.
   - Рекурсивное дерево подсистем (включая вложенные) и поиск объектов, не включённых ни в одну подсистему.

2. **Чтение данных и физических таблиц из `.dt` и `.1CD` (`tables`, `rows`)**
   - Автоматическая распаковка `.dt` в кэшированную файловую базу `1Cv8.1CD` (через установленную платформу `1cv8.exe` / `1cv8t.exe` в пакетном режиме).
   - Однопроходный точный подсчёт непустых записей и общего числа слотов во всех таблицах `.1CD`.
   - Чтение записей как по имени объекта (`Справочники.Номенклатура`, `Документы.РеализацияТоваровУслуг`), так и по табличным частям (`Объект.ТабличнаяЧасть`) или внутреннему имени таблицы (`_DOCUMENT334_VT345`).
   - Автоматический маппинг физических полей `_FLD*` в человекочитаемые имена реквизитов и разыменование бинарных `RREF`-ссылок (`_IDRREF`) в представления объектов.

3. **Извлечение исходного кода BSL (`module`)**
   - Оглавление всех модулей конфигурации с подсчётом строк кода (`--list`).
   - Извлечение модулей конфигурации (`МодульУправляемогоПриложения`, `МодульСеанса`, `МодульВнешнегоСоединения`), общих модулей, модулей объектов, менеджеров, набора записей, команд и форм.
   - Массовая выгрузка всех BSL-модулей конфигурации в каталог или единый дамп (`--all --out`).

4. **Разбор отчётов и схем СКД (`dcs`)**
   - Извлечение `DataCompositionSchema` из отчётов и обработок.
   - Разбор наборов данных, текстов запросов 1С, параметров, вычисляемых полей, ресурсов (итогов) и настроек вариантов отчётов, а также выгрузка чистого XML схемы (`--xml`).

5. **Формы, роли и пользователи ИБ (`forms`, `roles`, `users`)**
   - Инспекция управляемых и обычных форм: элементы, реквизиты, команды, привязки событий к процедурам и поиск «битых» обработчиков событий.
   - Детальный разбор прав ролей (`Rights.xml`) и поиск дублирующихся ролей.
   - Безопасное чтение списка пользователей ИБ из `V8USERS` (поле `DATA` с хэшами паролей автоматически маскируется).

6. **Перекрёстные ссылки, поиск и автоматический аудит (`xref`, `search`, `audit`)**
   - Поиск всех мест использования объекта по конфигурации (`xref`) и выявление неиспользуемых («мёртвых») объектов метаданных (`xref --unused`).
   - Быстрый текстовый/regex поиск по всем BSL-модулям или всему контейнеру (`search`).
   - Комплексный конфигурационно-независимый аудит (`audit`):
     - неиспользуемые объекты и объекты вне подсистем;
     - обращения к несуществующим значениям перечислений (`Перечисления.Х.У`) и объектам метаданных в BSL-коде;
     - несоответствие движений документа (`RegisterRecords`) и кода `ОбработкаПроведения`;
     - расхождения разрядности/точности чисел между документами/справочниками и регистрами;
     - битые обработчики событий форм;
     - антипаттерны в коде (запросы в циклах, пустые `Исключение`, `Выполнить()`, модальные вызовы);
     - сверка проведённых документов в базе с фактическими движениями в регистрах.

7. **Распаковка и сборка контейнеров (`unpack`, `build`, `raw`)**
   - Распаковка и сборка контейнеров `.cf`, `.cfe`, `.epf`, `.ert`, `.efd`, а также чтение сырых внутренних потоков (`DBNames`, `root`, `version`).

## 🚀 Установка и требования

### Требования
- **Python 3.10+**
- Библиотека [`onec-dtools`](https://pypi.org/project/onec-dtools/):
  ```bash
  pip install -r requirements.txt
  # или напрямую:
  pip install onec-dtools
  ```
- **Для работы с файлами выгрузки `.dt`**: локально установленная платформа **1С:Предприятие 8** (`1cv8.exe` или `1cv8t.exe`). Скрипт автоматически находит платформу в `C:\Program Files\1cv8` / `C:\Program Files (x86)\1cv8` (или через переменную окружения `ONEC_EXE`) и в фоновом режиме конвертирует `.dt` во временную кэшированную базу `1Cv8.1CD`. Для файлов `.1CD`, `.cf`, `.cfe`, `.epf`, `.ert`, `.efd` установленная платформа 1С **не требуется**.

### Установка в качестве плагина Antigravity / Gemini
Скопируйте папку `onec-inspector` в каталог плагинов:
- **Windows**: `%USERPROFILE%\.gemini\config\plugins\onec-inspector`
- **macOS / Linux**: `~/.gemini/config/plugins/onec-inspector`

## 💻 Использование из командной строки (CLI)

Задайте путь к скрипту:
```powershell
$SCRIPT = "skills/inspect-1c/scripts/onec_tool.py"
```

### 1. Обзор конфигурации и дерево подсистем
```powershell
python $SCRIPT summary "path/to/dump.dt" --subsystems
python $SCRIPT subsystems "path/to/dump.dt" --json
```

### 2. Автоматический аудит конфигурации и базы данных
```powershell
python $SCRIPT audit "path/to/dump.dt"
python $SCRIPT audit "path/to/dump.dt" --json
```

### 3. Детали объекта метаданных (реквизиты, типы, ТЧ, движения, перечисления)
```powershell
python $SCRIPT object "path/to/dump.dt" "РеализацияТоваровУслуг"
python $SCRIPT object "path/to/dump.dt" "Номенклатура" --class "Справочники" --json
```

### 4. Извлечение BSL-кода модулей
```powershell
# Список всех модулей конфигурации с количеством строк:
python $SCRIPT module "path/to/dump.dt" --list

# Код модулей конкретного объекта (включая модули его форм и команд):
python $SCRIPT module "path/to/dump.dt" "РеализацияТоваровУслуг"

# Корневые модули конфигурации (МодульУправляемогоПриложения, МодульСеанса и др.):
python $SCRIPT module "path/to/dump.dt" "Конфигурация"

# Выгрузка всех модулей конфигурации в папку:
python $SCRIPT module "path/to/dump.dt" --all --out "./exported_bsl"
```

### 5. Чтение таблиц и данных из `.dt` / `.1CD`
```powershell
# Список всех непустых таблиц базы данных с точным количеством записей:
python $SCRIPT tables "path/to/dump.dt" --non-empty

# Чтение записей справочника или документа (с именами реквизитов и расшифровкой ссылок):
python $SCRIPT rows "path/to/dump.dt" "Справочники.Номенклатура" --limit 20

# Чтение строк табличной части объекта:
python $SCRIPT rows "path/to/dump.dt" "РеализацияТоваровУслуг.Товары" --limit 50

# Чтение по физическому имени таблицы с фильтром:
python $SCRIPT rows "path/to/dump.dt" "_DOCUMENT334_VT345" --where "Количество" --raw-refs
```

### 6. Отчёты СКД, формы, роли и пользователи
```powershell
# Разбор всех схем компоновки данных (СКД):
python $SCRIPT dcs "path/to/dump.dt" --all
python $SCRIPT dcs "path/to/dump.dt" "ВедомостьПоТоварам" --xml

# Проверка управляемых и обычных форм:
python $SCRIPT forms "path/to/dump.dt" --all

# Роли и права доступа:
python $SCRIPT roles "path/to/dump.dt" --details

# Пользователи информационной базы (без раскрытия хэшей паролей):
python $SCRIPT users "path/to/dump.dt"
```

### 7. Поиск по коду и перекрёстные ссылки
```powershell
# Поиск неиспользуемых объектов метаданных:
python $SCRIPT xref "path/to/dump.dt" --unused

# Где используется конкретный объект:
python $SCRIPT xref "path/to/dump.dt" "ВидыНоменклатуры"

# Поиск подстроки по всем BSL-модулям (без учёта регистра):
python $SCRIPT search "path/to/dump.dt" "Запрос.Выполнить" --modules-only -i
```

### 8. Распаковка и сборка контейнеров (`.cf`, `.epf`, `.ert`, `.efd`)
```powershell
python $SCRIPT unpack "input.epf" "./unpacked_epf"
python $SCRIPT build "./unpacked_epf" "rebuilt.epf"
```

## 🔌 Инструменты MCP-сервера (`onec-inspector`)

Сервер `skills/inspect-1c/scripts/onec_mcp.py` реализует протокол MCP поверх `stdio` (JSON-RPC 2.0) без сторонних MCP-библиотек и предоставляет 14 инструментов:

| Инструмент | Назначение |
|---|---|
| `onec_summary` | Обзор конфигурации, свойства, классы метаданных, корневые модули |
| `onec_subsystems` | Рекурсивное дерево подсистем и объекты вне подсистем |
| `onec_object` | Реквизиты, типы, ТЧ, движения, перечисления, таблицы и формы объекта |
| `onec_modules` | Список модулей или извлечение BSL-кода объекта/конфигурации |
| `onec_dcs` | Схемы СКД: запросы, наборы данных, параметры, ресурсы, настройки, XML |
| `onec_forms` | Инспекция управляемых/обычных форм и проверка обработчиков событий |
| `onec_roles` | Роли, права доступа и поиск дубликатов ролей |
| `onec_users` | Безопасное чтение пользователей ИБ (`V8USERS`) |
| `onec_search` | Полнотекстовый или regex-поиск по BSL-модулям и потокам контейнера |
| `onec_xref` | Перекрёстные ссылки на объект и поиск неиспользуемых объектов |
| `onec_tables` | Список физических таблиц `.1CD` / `.dt` с подсчётом записей |
| `onec_rows` | Чтение строк таблиц и табличных частей с расшифровкой `_FLD` и `RREF` |
| `onec_audit` | Полный автоматический аудит конфигурации, BSL-кода, форм, ролей и данных |
| `onec_raw` | Чтение низкоуровневых потоков контейнера (`DBNames`, `root`, `version`) |

---

## 🔒 Безопасность

- Инструменты `users` и `rows` автоматически маскируют бинарное поле `DATA` таблицы `V8USERS` (`<REDACTED V8USERS.DATA N bytes>`), исключая утечку хэшей паролей.
- Инструмент не использует `DESIGNER /DumpConfigToFiles`, который может зависать на модальных окнах, а читает бинарные структуры `.1CD` и `.cf` напрямую через `onec_dtools`.
